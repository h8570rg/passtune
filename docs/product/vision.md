# Vision / Problem Definition

- Phase: 1
- Last updated: 2026-09-28
- 状態: 起案中。`[DECIDED]` は開発者の発言そのもの、それ以外は AI の起案・解釈。

## 1. Project Purpose

- [DECIDED] 友人間の狭いコミュニティで、**自分が使いたいもの** を作る。
- [DECIDED] 目的は、お互いに好きな音楽を共有すること。
- [DECIDED] マネタイズとスケールは今は目標にしない。ただし将来できる余地は残したい。
- [DECIDED] 予算は潤沢ではない。ランニングコストは抑える。

### 「将来できる余地を残す」の解釈 [PROPOSED]

「将来に備えて作り込む」ことではなく、**取り返しのつかない選択を避ける（可逆性を保つ）** ことと解釈する。

- やる: 選択肢を選ぶとき、その選択で将来の商用化や公開が **不可能になるか** を確認する（例: API 規約の商用利用・ユーザー数の制限）。
- やらない: 多数ユーザー向けのスケール対策、課金機能、公開 SNS 向けの機能（モデレーション等）の先回り実装。

## 3. Target User

- [ASSUMPTION] 開発者本人と、その友人（数人〜数十人規模）。
- [OPEN] 実際に使ってほしい友人は何人か。
- [OPEN] 友人たちが使っているサブスク（Spotify / Apple Music / YouTube Music / サブスクなし等）の分布。

## 4. Vision [PROPOSED]

> 仲の良い友人同士が、使っている音楽サービスの違いを気にせず、好きな曲を気軽に届け合い、聴き合える場所。

## 5. Problem Hypotheses

誰の・どんな困りごとか。Phase 2 で、自分と友人で確かめる。

| ID | Hypothesis | 確かめ方（案） |
|---|---|---|
| H1 | [HYPOTHESIS] 友人とサブスクが違うと、共有されたリンクを開いて聴くまでに手間がかかり、結局聴かれない | 自分と友人が最近受け取った共有を、実際に聴いたかどうか振り返る |
| H2 | [HYPOTHESIS] LINE などのチャットで共有すると会話に流れて埋もれ、後から見返せない | 同上。「前に誰かが勧めてた曲」を探した経験があるか |
| H3 | [HYPOTHESIS] 個別に DM で送ると相手に反応を強いるように感じ、共有をためらう。タイムラインに「置く」形なら気軽に共有できる | 共有をためらった経験があるか、その理由 |
| H4 | [HYPOTHESIS] その場で試聴できれば、聴くかどうかを決める手間が下がり、聴かれる曲が増える | 共有されても聴かなかった理由を聞く |
| H5 | [HYPOTHESIS] 友人が好きな曲を知ること自体に価値がある（音楽を介したコミュニケーション） | 友人の好きな曲を知りたいと思うか |

## 6. Non-goals（当面やらないこと）[PROPOSED]

- 知らない人とのつながりや、不特定多数への公開
- 収益化
- 大規模ユーザー向けの機能・設計

## 7. Solution Ideas（未決定）

開発者の現時点のアイデア。採否は Phase 7〜8 で、上の問題仮説との対応で判断する。

- 曲名検索での投稿
- Spotify / Apple Music のリンクでの投稿
- タイムライン表示
- タイムライン上でのプレビュー（試聴）再生（→ H4）
- 閲覧者が自分の使っているサブスクで開けるリンク（→ H1）

## 8. 早めに調べるべき外部リスク（調査のみ、決定しない）

アイデアの実現性を左右しうるため、Phase 5 を待たずに一次情報で確認する。以下は AI の記憶に基づく **未確認情報**。

- [OPEN] Spotify Web API で、新規アプリはプレビュー音源を取得できなくなったのではないか（2024年末ごろの変更と記憶）
- [OPEN] Spotify の開発モードには利用ユーザー数の上限があり、拡張の審査条件が厳しくなったのではないか（友人規模なら上限内に収まる可能性）
- [OPEN] Apple 側（iTunes Search API / MusicKit）でのプレビュー取得の可否、利用条件、費用（Apple Developer Program の年会費など）
- [OPEN] サービス間での同じ曲の対応付け（リンク変換）の方法と、その利用条件
- [OPEN] 各 API の規約上、友人限定の非商用利用と、将来の商用利用が許されるか
