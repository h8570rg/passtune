# Vision / Problem Definition

- Phase: 1
- Last updated: 2026-09-28
- 状態: 起案中。`[DECIDED]` は開発者の発言そのもの、それ以外は AI の起案・解釈。

## 1. Project Purpose

- [DECIDED] 友人間の狭いコミュニティで、**自分が使いたいもの** を作る。
- [DECIDED] 目的は、お互いに好きな音楽を共有すること。
- [DECIDED] マネタイズは今は目標にしない。ただし将来できる余地は残したい。
- [DECIDED] 友人以外にも使ってほしい。不特定多数への公開はやりたい（ユーザーは増やしたい）。
  - 2026-09-28 更新: 当初の「スケールは今は目標にしない」を開発者が変更。
  - [OPEN] 「最初の友人20人に使われること」と「友人以外へ広げること」の優先順位、公開の形（→ 3. Target User）
- [DECIDED] 予算は潤沢ではない。ランニングコストは抑える。

### 「将来できる余地を残す」の解釈 [DECIDED]

「将来に備えて作り込む」ことではなく、**取り返しのつかない選択を避ける（可逆性を保つ）** ことと解釈する。

- やる: 選択肢を選ぶとき、その選択で将来の商用化や公開が **不可能になるか** を確認する（例: API 規約の商用利用・ユーザー数の制限）。
- やらない: 多数ユーザー向けのスケール対策、課金機能、公開 SNS 向けの機能（モデレーション等）の先回り実装。

## 3. Target User

- [DECIDED] 最初のユーザー: 開発者本人と友人 約 20 人。
- [DECIDED] 友人以外（不特定多数）にも公開する。
- [ASSUMPTION] 友人は Apple Music 利用者が多い（開発者の印象。未確認）。
- [OPEN] 開発者本人が使っているサービス。
- [OPEN] 公開の形。例: (a) 誰でも登録できるが、体験の中心はフォローした知り合い同士 / (b) 知らない人の投稿も流れてくる発見型。

## 4. Vision [DECIDED]

> 仲の良い友人同士が、使っている音楽サービスの違いを気にせず、好きな曲を気軽に届け合い、聴き合える場所。

- [OPEN] 不特定多数への公開を踏まえ、「仲の良い友人同士」の部分を広げるか（公開の形が決まってから見直す）。

## 5. Problem Hypotheses

### 現状の共有方法（開発者の回答, 2026-09-28）

- 音楽を共有する手段がほとんどない。
- X（Twitter）に「これおすすめ！」と投稿するか、口頭で伝える程度。

誰の・どんな困りごとか。Phase 2 で、自分と友人で確かめる。

| ID | Hypothesis | 確かめ方（案） |
|---|---|---|
| H1 | [HYPOTHESIS] 友人とサブスクが違うと、共有されたリンクを開いて聴くまでに手間がかかり、結局聴かれない | 自分と友人が最近受け取った共有を、実際に聴いたかどうか振り返る |
| H2 | [HYPOTHESIS] LINE などのチャットで共有すると会話に流れて埋もれ、後から見返せない | 同上。「前に誰かが勧めてた曲」を探した経験があるか |
| H3 | [DEPRECATED] DM で送る気まずさ → 現状 DM では共有していないため H7 に置き換え | ― |
| H4 | [HYPOTHESIS] その場で試聴できれば、聴くかどうかを決める手間が下がり、聴かれる曲が増える | 共有されても聴かなかった理由を聞く |
| H5 | [HYPOTHESIS] 友人が好きな曲を知ること自体に価値がある（音楽を介したコミュニケーション） | 友人の好きな曲を知りたいと思うか |
| H6 | [HYPOTHESIS] 音楽を共有する専用の場がないため、共有したい気持ちがあっても共有の回数そのものが少ない | 「共有したかったけどしなかった」経験の有無と頻度 |
| H7 | [HYPOTHESIS] X は音楽に関心のないフォロワーにも届き、他の投稿に埋もれるため、音楽の投稿がしづらい / 見られにくい | X での音楽投稿への反応、投稿をためらった経験 |
| H8 | [HYPOTHESIS] 口頭で勧められた曲は記録に残らず、後で聴かれない | 口頭で勧められた曲を実際に聴いたか |

アイデアの実現性を左右しうるため、Phase 5 を待たずに一次情報で確認する。以下は AI の記憶に基づく **未確認情報**。

- [OPEN] Apple 側（iTunes Search API / MusicKit）でのプレビュー取得の可否、利用条件、費用（Apple Developer Program の年会費など）
- [OPEN] サービス間での同じ曲の対応付け（リンク変換）の方法と、その利用条件
- [OPEN] 各 API の規約上、不特定多数への公開と、将来の商用利用が許されるか
- [OPEN] Apple Developer Program の年会費（未確認だが年 1 万円を超える可能性）。Apple Music 連携やネイティブ iOS アプリで必須になる場合、それだけで予算目安を超える
- [OPEN] 不特定多数に公開する場合の義務・負担（利用規約・プライバシーポリシー、通報やモデレーション、個人情報の扱い）

## 9. Success Criteria [OPEN]

案: 「自分と友人 10 人（約 20 人の半数）が、公開から 3 か月後も週 1 回以上投稿または試聴している」。
友人以外への広がりの指標は、公開の形が決まってから置く。
