# Vision / Problem Definition

- Phase: 1
- Last updated: 2026-09-28
- 状態: Phase 1 完了（2026-09-28）。`[DECIDED]` は開発者が確定したもの、それ以外は AI の起案・解釈。

## 1. Project Purpose

- [DECIDED] 友人間の狭いコミュニティで、**自分が使いたいもの** を作る。
- [DECIDED] 目的は、お互いに好きな音楽を共有すること。
- [DECIDED] マネタイズは今は目標にしない。ただし将来できる余地は残したい。
- [DECIDED] 友人以外にも使ってほしい。不特定多数への公開はやりたい（ユーザーは増やしたい）。
  - 2026-09-28 更新: 当初の「スケールは今は目標にしない」を開発者が変更。
  - 公開の形と優先順位は [002](../decisions/002-audience-and-openness.md) で決定。
- [DECIDED] 予算は潤沢ではない。ランニングコストは抑える。

### 「将来できる余地を残す」の解釈 [DECIDED]

「将来に備えて作り込む」ことではなく、**取り返しのつかない選択を避ける（可逆性を保つ）** ことと解釈する。

- やる: 選択肢を選ぶとき、その選択で将来の商用化や公開が **不可能になるか** を確認する（例: API 規約の商用利用・ユーザー数の制限）。
- やらない: 多数ユーザー向けのスケール対策、課金機能、公開 SNS 向けの機能（モデレーション等）の先回り実装。

## 3. Target User

- [DECIDED] 最初のユーザー: 開発者本人と友人 約 20 人。
- [DECIDED] 友人以外（不特定多数）にも公開する。
- [ASSUMPTION] 友人は Apple Music 利用者が多い（開発者の印象。未確認）。
- [DECIDED] 開発者本人は Spotify を使っている。→ 開発者（Spotify）と友人（Apple Music が多い）の間でサービスが違うこと自体が、H1 の実例になっている。
- [DECIDED] 公開の形は「知り合い中心で、誰でも参加できる」。まず友人 20 人の体験を優先する（[002](../decisions/002-audience-and-openness.md)）。

## 4. Vision [DECIDED]

> 仲の良い友人同士が、使っている音楽サービスの違いを気にせず、好きな曲を気軽に届け合い、聴き合える場所。

- 公開の形が「知り合い中心」に決まったため、Vision の文言は変えない。

## 5. Problem Hypotheses

### 現状の共有方法（開発者の回答, 2026-09-28）

- 音楽を共有する手段がほとんどない。
- X（Twitter）に「これおすすめ！」と投稿するか、口頭で伝える程度。

誰の・どんな困りごとか。H6〜H8 は開発者本人が「課題である」と回答済み（n=1）。Phase 2 で友人でも確かめる。

| ID | Hypothesis | 確かめ方（案） |
|---|---|---|
| H1 | [HYPOTHESIS] 友人とサブスクが違うと、共有されたリンクを開いて聴くまでに手間がかかり、結局聴かれない | 自分と友人が最近受け取った共有を、実際に聴いたかどうか振り返る |
| H2 | [HYPOTHESIS] LINE などのチャットで共有すると会話に流れて埋もれ、後から見返せない | 同上。「前に誰かが勧めてた曲」を探した経験があるか |
| H3 | [DEPRECATED] DM で送る気まずさ → 現状 DM では共有していないため H7 に置き換え | ― |
| H4 | [HYPOTHESIS] その場で試聴できれば、聴くかどうかを決める手間が下がり、聴かれる曲が増える | 共有されても聴かなかった理由を聞く |
| H5 | [HYPOTHESIS] 友人が好きな曲を知ること自体に価値がある（音楽を介したコミュニケーション） | 友人の好きな曲を知りたいと思うか |
| H6 | [HYPOTHESIS]（本人確認済み）音楽を共有する専用の場がないため、共有したい気持ちがあっても共有の回数そのものが少ない | 「共有したかったけどしなかった」経験の有無と頻度 |
| H7 | [HYPOTHESIS]（本人確認済み）X は音楽に関心のないフォロワーにも届き、他の投稿に埋もれるため、音楽の投稿がしづらい / 見られにくい | X での音楽投稿への反応、投稿をためらった経験 |
| H8 | [HYPOTHESIS]（本人確認済み）口頭で勧められた曲は記録に残らず、後で聴かれない | 口頭で勧められた曲を実際に聴いたか |

## 8. 外部リスク（調査のみ、決定しない）

初回調査: [research/2026-09-28-music-api-feasibility.md](../research/2026-09-28-music-api-feasibility.md)

- Spotify のユーザーログイン連携は、開発モードでは 5 人まで。上限を外す申請は法人かつ MAU 25 万以上が条件で、個人では不可。
- Spotify API ではプレビュー音源が取れない。Apple の iTunes Search API はキーなしで取れるが、利用条件がある。
- Apple Developer Program（約 12,980 円/年）が必要になる構成だと、予算の目安を超える。
- サービス間リンク変換の Odesli はキーなしの利用が廃止された。
- [OPEN] 一般公開時の義務（利用規約・プライバシーポリシー・通報対応・個人情報の扱い）は未調査。
