## 1. Strategy in one line [PROPOSED]

> 知り合い同士が「意図して 1 曲を勧める」ことに絞り、サービスの違いを気にせず、リンク 1 つですぐ試聴して反応できる場をつくる。

## 2. Where to play / How to win [PROPOSED]

| | 内容 |
|---|---|
| 誰のために | 開発者（Spotify）と友人約 20 人（Apple Music が多い）。次に、友人の友人 |
| どんな場面で | 「この曲いい、あの人に聴いてほしい」と思ったとき |
| 何で勝つか | ①すぐ試聴できる（サービスの違いを問わない） ②リンク 1 つで、登録前から価値が伝わる ③日本の楽曲に強い照合 |
| 戦わない場所 | 今聴いている曲の自動共有（Airbuds）、DM（Spotify Messages）、知らない人との出会い・発見 |

## 3. Core Loop（仮説）[HYPOTHESIS]

利用が続く仕組みの仮説。MVP（Phase 8）はこのループが回るかを確かめる最小単位にする。

```
① 1 曲＋一言を投稿
  → ② 投稿のリンクを LINE / X に貼る（R2 の対策）
  → ③ 友人が、登録なしでその場で試聴する（H4 / H1）
  → ④ 反応したくなり、参加する（いいね・コメント）
  → ⑤ 投稿者に反応と再生回数が届く（H9）
  → ①に戻る（投稿者はまた投稿したくなる / 参加した友人も投稿する）
```

- タイムラインの過疎（R1）は、ループの入口を「タイムラインを毎日見に来ること」ではなく「LINE / X で届いたリンク」と「新しい投稿の通知」にすることで和らげる。

## 4. Product Principles [PROPOSED]

判断に迷ったときの優先順位。上ほど優先する。

1. **聴くまでの手間を最小にする。** 試聴は最優先の体験。
2. **サービスの違いを意識させない。** 投稿者も閲覧者も、自分のサービスのまま使える。
3. **参加する前に価値が伝わる。** 登録やインストールなしで試聴できる。
4. **投稿は軽く。** 1 曲＋一言。気が向いたときだけでよい。
5. **聴く側に負担をかけない。** 誰が聴いたかは見せない。毎日開くことを求めない。
6. **小さく、安く、保守しやすく。** DM・アップロードなし。外部 API への依存は曲の検索・情報・試聴に限る。

## 5. Do / Don't [PROPOSED]

| やる | やらない（当面） |
|---|---|
| 1 曲の投稿＋一言 | アルバム・プレイリスト単位の共有 |
| サービスをまたいだ試聴と、各自のサービスへのリンク | Spotify / Apple Music のユーザー連携（ログイン・再生履歴の取得） |
| いいね・その他のリアクション・コメント | DM（決定済み） |
| 投稿者だけが見る再生回数 | 誰が聴いたかの表示 |
| 知り合い同士のつながり（フォロー等） | おすすめ・全体タイムライン・知らない人との出会い |
| 最低限の通報・削除・ブロック、利用規約・プライバシーポリシー | 画像・音声・動画のアップロード（決定済み）、収益化 |

## 6. Stages [PROPOSED]

| Stage | 対象 | 目標 | 次に進む条件 |
|---|---|---|---|
| 1 | 開発者＋友人約 20 人 | Core Loop が回る | 成功基準: 友人 10 人が公開 3 か月後も週 1 回以上使っている |

| 3 | 一般 | [002](../decisions/002-audience-and-openness.md) を見直し、発見型の機能を検討する | ― |

## 7. Metrics（案）[PROPOSED]

- 成功基準（決定済み）: 友人 10 人が公開 3 か月後も週 1 回以上、投稿または試聴している
- ループを見るための補助指標:
  - 週あたりの投稿数
  - 投稿あたりの試聴数
  - 登録なしで試聴した人のうち、参加した人の割合
