## 1. プロダクトを殺しうるリスク（最優先）

| ID | リスク | 可能性 | 影響 | 対応の方向性 [DECIDED] |
|---|---|---|---|---|
| R1 | **タイムラインが空になる。** 投稿は不定期で、友人 20 人規模では新しい投稿がない日が続き、見に来る理由がなくなる | 高 | 高 | 「毎日開かせる」ことを前提にしない。新しい投稿に気づける仕組みを用意する（入口がリンク共有ではないため、特に重要）。過去の投稿も楽しめるようにする。開発者自身が最初の投稿者として場を温める（Phase 7 で比較） |
| R2 | **友人が参加しない。** 20 人それぞれにアカウント作成やインストールを求める壁 | 高 | 高 | 開発者が直接声をかけて登録してもらう。登録・参加の手間を小さくする（Phase 7 で比較）。※2026-09-28 変更: 当初の「LINE / X へのリンク共有で登録前に価値を伝える」は、開発者がその使い方を想定しないため取り下げ |
| R3 | **試聴が実現できない / 使えなくなる。** 試聴は Apple の iTunes Search API 頼み。Spotify は 2 年で 3 回 API を制限した。Apple の文書もアーカイブ扱い | 中 | 高 | 「Spotify のユーザー連携」には最初から依存しない。外部 API への依存は「曲の検索・情報・試聴」に限定し、差し替えられる範囲にしておく（過剰な抽象化はしない） |

## 2. 体験の質に関わるリスク

| ID | リスク | 可能性 | 影響 | 対応の方向性 [DECIDED] |
|---|---|---|---|---|
| R4 | **曲の照合を間違える / 照合できない。** Spotify の曲に対応する Apple の曲が見つからない、別バージョンや日本語表記の揺れで取り違える | 中 | 中 | 投稿時に「この試聴で合っているか」を投稿者自身が確認する。照合できない曲は試聴なしで、リンクのみにする |

## 3. 一般公開に伴うリスク

根拠: [一般公開する SNS の法的義務](../research/2026-09-28-public-service-obligations.md)（法的助言ではない）

| ID | リスク | 可能性 | 影響 | 対応の方向性 [DECIDED] |
|---|---|---|---|---|
| R6 | **法的義務の見落とし。** 個人情報保護法・外部送信規律・電気通信事業法 | 確実に関係する | 中 | 公開前に利用規約・プライバシーポリシーを用意する。**DM 機能は持たない（決定済み）**（届出と通信の秘密の義務を避ける） |
| R7 | **荒らし・スパム・不適切なコメント** | 低（知り合い中心のため） | 中 | 公開時に最低限の通報・削除・ブロックを用意する。画像アップロードは持たない（決定済み） |
| R8 | **アカウントの乗っ取り・情報漏えい** | 低〜中 | 中 | パスワードを自前で保存しない方式を優先する（Phase 9） |
| R9 | **費用の超過。** ネイティブアプリで Apple Developer Program が必要になる、ユーザー増で無料枠を超える | 中 | 中 | Web かネイティブかの判断（Phase 9）で、費用を比較の軸に入れる |

## 4. 決定事項

- [DECIDED] DM 機能は持たない。交流は、投稿へのリアクションとコメントに限る（R6）。
