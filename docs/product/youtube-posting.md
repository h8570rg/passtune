## 2. YouTube の 3 種類の違い

3 種類とも、中身は同じ「動画 ID」で表される（`youtube.com/watch?v=ID`、`youtube.com/shorts/ID`、`music.youtube.com/watch?v=ID`）。

| | 通常の動画（MV など） | Shorts | YouTube Music の曲 |
|---|---|---|---|
| 中身 | 公式 MV、ライブ、カバー、切り抜きなど | 3 分以内の縦動画。曲の一部を使った投稿が多い | 「〜 - Topic」の音源（静止画）か、公式 MV |
| 埋め込み | できる（所有者が無効にした動画は不可） | `/embed/ID` でできる（縦長） | できる（同上） |
| 曲として特定できるか | 中（タイトルの書き方がばらばら） | **低**（タイトルは自由。使っている曲の情報は API で取れない） | **高**（タイトル＝曲名、チャンネル＝「アーティスト - Topic」） |
| 形 | 横 16:9 | 縦 9:16 | 横 16:9（中は静止画） |
| 開始位置のリンク | `&t=秒` | 短いので不要 | `&t=秒`（アプリの共有にも「開始位置」がある） |

## 3. 制約（事実）

- **プレーヤーは見せる必要がある。** 音声と映像の分離、見えないプレーヤーでの再生、プレーヤーを隠すことは禁止。200×200px 以上。広告を消すことも禁止（YouTube API Services Developer Policies III.I）。
  - → 今の試聴（音だけの小さな再生ボタン）と同じ見せ方はできない。
- **広告が流れることがある。** 公式 MV などは再生前に広告が入ることがある（YouTube Premium 会員以外）。「サビからすぐ」が広告で崩れうる。
- **iPhone では 2 回タップが必要なことがある。** 押してからプレーヤーを読み込む作りだと、Safari は自動再生を止める。YouTube の IFrame API を使えば iPhone では「たいてい」1 回で済むが、確実ではない（lite-youtube-embed の作者の記述、WebKit のバグ報告）。友人は iPhone が多い。
- **埋め込みできない動画がある。** 所有者が埋め込みを無効にした動画、年齢制限のある動画など。oEmbed（キー不要）が 401 を返す、または Data API の `status.embeddable` で事前に分かる。
- **YouTube のデータは 30 日を超えて保存できない**（タイトル・サムネイル・再生回数など。III.E.4）。動画 ID 自体の扱いは明記がない。
- **費用は 0。** Data API は無料（検索は 1 日 100 回、ほかは 1 日 10,000 ユニット）。Google Cloud のプロジェクト（Google ログイン用と同じ）で API キーを発行する。
- **プライバシー。** 埋め込みプレーヤーは閲覧データを集めるので、プライバシーポリシーへの追記と YouTube 利用規約へのリンクが必要。`youtube-nocookie.com`（プライバシー強化モード）を使える。

## 4. いちばん大きな分かれ道: 投稿の「主役」は何か

| | X. 曲が主役（YouTube は聴き方） | Y. 動画も主役にできる |
|---|---|---|
| 投稿 | いつも「1 曲」。YouTube の動画は、その曲を聴く手段として添える | 「1 曲」か「1 本の動画」 |
| Shorts・ライブ・カバー | 曲を特定できれば添えられる。曲がなければ投稿できない | 投稿できる |
| 各サービスで開く | 全投稿で Apple Music・Spotify・LINE MUSIC が使える | 動画の投稿は YouTube だけ |
| 見た目 | 全投稿が同じ（ジャケット・曲名・アーティスト） | 2 種類のカードになる |
| データ | 今の表に YouTube の列を足すだけ | Apple の曲 ID が空の投稿ができ、分岐が増える。動画のタイトルを保存すると 30 日ルールにかかる |
| 原則との相性 | 「サービスの違いを意識させない」を守れる | 動画は誰でも無料で見られるので、聴けないわけではない。ただ「1 曲を勧める」から広がる |
| 後から変えられるか | X → Y は足すだけ | Y → X は投稿の扱いが残る |

- **AI の推奨: X から始める。** 一貫性を保ったまま P1〜P3 をすべて解決できる。Y は「曲が見つからない動画も投稿したい」が実際に何度も起きてから足す。

## 5. X の場合の設計案

### 投稿する

- **入口 1: 曲名で検索（今と同じ）→ 聴きどころを添える（任意）**
  1. 曲を選ぶと、YouTube の候補を出す（Data API の検索。「- Topic」と公式チャンネルを上に）。
  2. 候補を選ぶとプレーヤーが開く。好きな位置まで動かして「ここから聴かせる」。
- **入口 2: YouTube のリンクを貼る**
  1. 検索欄に YouTube・YouTube Music・Shorts のリンクを貼る（`youtu.be` も可）。
  2. 動画の情報から曲を推定し、Apple の候補を出す。投稿者が「この曲」と確かめる（Shorts は推定できないので、曲名で探してもらう）。
  3. リンクの `t=` があれば、それを聴きどころにする。
- 動画を選んだ時点で埋め込みできるか確かめ、できなければ「この動画は Passtune では再生できません」と出す。
- 後で: Android のホーム画面に追加した Passtune を、YouTube アプリの「共有」から選べるようにする（Web Share Target。iPhone の PWA は非対応）。

### 聴く

| 案 | 再生ボタンを押すと | 良い点 | 悪い点 |
|---|---|---|---|
| ① YouTube を主にする | 聴きどころの動画がカードの中に開いて流れる。YouTube がない投稿は今の試聴 | 押すだけでサビ。ボタンは 1 つ | 広告が入ることがある。iPhone で 2 回タップのことがある。通信量が多い |
| **② 試聴はそのまま、YouTube を足す** | 今の試聴が流れる。「聴きどころから（YouTube）」を押すと動画が開く | 試聴はすぐ鳴る・広告なし。今の体験を壊さない | ボタンが 2 つになる。サビまでの手間が 1 回増える |

- **AI の推奨: ②から始め、試作で広告と iPhone の挙動を確かめてから①を検討する。**
- 共通:
  - 同時に開くプレーヤーは 1 つ。別の試聴や動画を始めたら、前のものは止める（IFrame API の `pauseVideo`）。
  - 縦の Shorts は、カードの中で高さを抑えて中央に置く。
  - 延べ再生回数は、YouTube の再生開始でも数える。
  - 再生できなくなった動画（削除・非公開）は、エラーを受けてリンクだけにする。

### 各サービスで開く

- YouTube が添えられた投稿は、「YouTube Music」のボタンを曲の画面へ直接飛ばす（`music.youtube.com/watch?v=ID&t=秒`）。今の検索結果より良くなる（P3）。
- Apple Music・Spotify は開始位置を指定できないので、ボタン列の近くに「聴きどころ 1:05〜」と文字で出す。どのサービスの人にも、どこを聴いてほしいかが伝わる。

### データ

- `posts` に `youtube_video_id`（任意）、`youtube_start_seconds`（任意）、`youtube_format`（`video` / `short`）を足す。Apple の曲 ID は今のまま必須。
- 保存するのは動画 ID と開始位置（投稿者が選んだもの）だけ。YouTube のタイトル・サムネイル・再生回数は保存しない（30 日ルール）。表示は今どおり Apple の情報を使う。
