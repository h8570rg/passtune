## 1. MVP の位置づけ [DECIDED]

開発者の回答（2026-09-28）:

- 招待制の小さな試作ではなく、**完成に近い形** で作る。
- MVP の評価は、**本番ではない環境で開発者自身が触るだけ** で行う。他のユーザーには MVP を触ってもらわない。
- 友人が初めて触るのは、公開（Launch）の時点になる。

### 当初方針からの変更点

- [003](../decisions/003-user-research-approach.md) と R5 の対応として置いていた「友人に早く触ってもらう」は、この方針により取らない。
- 友人側の仮説（R1 過疎、R2 参加、H9 反応）が初めて確かめられるのは、公開後になる。
- トレードオフ（AI の意見）:
  - 公開前に作る量が増えるので、友人の反応が想定と違ったときの作り直しコストが大きくなる。
  - 開発期間が延びる分、意欲が切れるリスク（R5）も上がる。
  - 対策として、公開後に計測して直せるように、「確かめたいこと」（下記 2.）の数字は公開時点で見られるようにしておく。

## 2. 確かめたいこと

| いつ | 問い | 見るもの |
|---|---|---|
| MVP（開発者のみ） | 自分が使いたいものになっているか。投稿・試聴・各自のサービスで開く流れにストレスがないか | 開発者の使用感 |
| 公開後 | 声をかけた友人は登録するか（R2） | 声をかけた人数に対する登録者数 |
| 公開後 | 試聴できると、勧めた曲が聴かれるか（H4 / H1） | 投稿あたりの延べ再生回数 |
| 公開後 | 反応があると、投稿が続くか（H9） | 週あたりの投稿数、いいね・コメント数 |
| 公開後 | 暇なときに開いて、見るものがあるか（R1） | 週に 1 回以上開く人の数 |

判定: 成功基準（決定済み）の「友人 10 人が、公開 3 か月後も週 1 回以上、投稿または試聴している」。

## 3. 範囲 [PROPOSED]

### 入れる（Must）

| 機能 | 内容 | 根拠 |
|---|---|---|
| 登録・ログイン | 手間の少ない方法（方式は Phase 9） | 原則 3 |
| 招待リンク | 招待リンクから登録すると、招待した人を自動でフォローする。その人がフォローしている人をまとめてフォローできる | D1 / D2 |
| フォロー | フォロー / フォロー解除 | 決定済み |
| 投稿 | 曲名検索で曲を選び、一言を付けて投稿する。候補から投稿者が選ぶ・確認する | A1 |
| 投稿（リンクから）[Should] | Apple Music / Spotify のリンクから投稿する。難しければ MVP から外し、曲名検索だけにする（開発者回答） | A2 / A3 |
| 試聴 | Apple の試聴音源を再生する。出典表示と Apple Music へのリンクを付ける | B1 |
| 各自のサービスで開く | 設定で使っているサービス（Spotify / Apple Music / YouTube Music）を選ぶ。そのサービスで開くボタンを出す | C1 |
| タイムライン | フォローしている人の投稿を時系列で表示し、過去もさかのぼれる | E1 |
| いいね・コメント | いいねのみ。コメントに返信機能はなし | F |
| 延べ再生回数 | 投稿者だけが見られる | F |
| プロフィール | その人の過去の投稿一覧 | E3 |
| 自分の投稿・コメントの削除 | ― | 最低限の運営 |
| プライバシーポリシー・利用規約 | 個人情報を扱う以上、友人だけの段階でも必要 | R6 |

### 入れない（MVP の後で検討）

| 機能 | 理由 |
|---|---|
| 通知（プッシュなど） | [DECIDED] MVP には入れない（開発者回答） |
| 反応を確認する専用画面（E2） | MVP では、自分の投稿に付いたいいね・コメント・再生回数を投稿自体で確認できれば足りる |
| ログインなしでの閲覧 | 広げる手段として位置づけておらず、Stage 1 には不要 |
| 誰でも登録できる状態、通報・ブロック | Stage 1 は招待リンク経由の登録に限る（下記） |
| 絵文字リアクション、過去投稿の掘り起こし（E4） | 必要と分かってから足す |

### 公開の形（[OPEN] 開発者に確認中）

招待制で始める案は、開発者の回答（完成に近い形で作る）により取り下げ。「完成に近い形」に次を含めるかを確認中。

- 誰でも登録できる状態と、そのための通報・ブロック
- ログインなしでの閲覧
- 反応を確認する専用画面

## 4. Spotify のリンクからの投稿の実現方法 [PROPOSED]（Should の場合）

- まずは Spotify API を使わず、キーなしで取れる曲名（oEmbed）で Apple 側を検索し、候補から投稿者が選ぶ形にする。
- アーティスト名がないため候補がぶれやすい。使ってみて選びにくければ、Spotify API（ログイン不要の方式）でアーティスト名を取る形に変える。
- 理由: 外部依存を最小にする（原則 6、R3）。
- 根拠: [曲の照合実験](../research/2026-09-28-song-matching.md)
