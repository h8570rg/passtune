# 004: プロダクト戦略

- Status: DECIDED
- Date: 2026-09-28
- Area: Product
- Related: [strategy.md](../product/strategy.md)（詳細はこちらが正本）, [risks.md](../product/risks.md), [002](002-audience-and-openness.md)

## Context

Phase 1〜5 の結果（Vision、開発者ヒアリング、競合調査、API 制約、リスク）をもとに、何をやり何をやらないかを決める。

## Options considered

主な分岐は 3 つ。

| 論点 | Option | 結果 |
|---|---|---|
| 広げ方 | (a) 投稿のリンクを LINE / X で共有し、登録前に価値を伝える | 不採用: 開発者がその使い方を想定しない |
| | (b) 開発者が友人に直接声をかけ、登録してもらう | 採用 |
| つながり方 | (a) 片方向フォロー | 採用 |
| | (b) グループ | 見送り: 境界管理や重複表示が複雑になる |
| 対象端末 | iPhone のみ / Android のみ / 両方 | 両方: 開発者は Android、友人は iPhone が多い |

## Decision

[strategy.md](../product/strategy.md) の内容で確定する。要点は次のとおり。

- 知り合い同士が「意図して 1 曲を勧める」ことに絞る。
- サービスの違いを問わずすぐ試聴でき、反応できる。
- 広げ方は、開発者の直接の声かけ。
- つながりは片方向フォロー。通知は各自の設定。
- iPhone と Android の両方で使えるようにする。
- プロダクト原則は 6 つ（上ほど優先）: 聴くまでの手間を最小にする / サービスの違いを意識させない / 参加の手間を小さくする / 投稿は軽く / 聴く側に負担をかけない / 小さく、安く、保守しやすく。

## Why

- 開発者本人の使い方（暇なときに開く、通知は設定次第）と要望（試聴・反応）に合わせた。
- 競合（Airbuds、Spotify Messages）と役割が分かれる。
- API 制約・費用・法的義務（DM なし）の範囲に収まる。

## Tradeoffs / Consequences

- 入口がリンク共有ではない。そのため、タイムラインの過疎（R1）への対策は「暇なときに開いて見るものがある」ことと「登録直後のフォロー」にかかる。
- フォロー制なので、登録直後のタイムラインが空になりやすい。

## Revisit when

- Stage 1 の成功基準が満たせず、原因が「見るものがない」「友人が参加しない」にあるとき（リンク共有やグループを再検討）
- Stage 3（一般公開の拡大）に進むとき
