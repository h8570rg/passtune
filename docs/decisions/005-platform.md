# 005: 提供形態

- Status: DECIDED
- Date: 2026-09-28
- Area: Technical
- Related: [platform-options](../research/2026-09-28-platform-options.md), [multiplatform-approach](../research/2026-09-28-multiplatform-approach.md), [ios-pwa-adoption](../research/2026-09-28-ios-pwa-adoption.md), [mvp](../product/mvp.md), [004](004-product-strategy.md)

## Context

- iPhone と Android の両方で使えることが条件（[004](004-product-strategy.md)）。開発者は Android、友人は iPhone が多い。
- 開発者は Web フロントエンドのエキスパート。ネイティブは未経験。開発・保守は 1 人（週 約 10 時間）。
- 開発者は当初、Web・iOS・Android すべてで提供したいと考えた。Web ではホーム画面に置いてもらうハードルが高いため。
- 検討の中で分かったこと:
  - Google Play は、個人アカウントだと本番公開に 12 人 × 14 日のクローズドテストが必要。組織アカウントなら免除されるが、それには開業届が要る。開発者は開業届を出さない。
  - Web を包んだだけのアプリは、App Store の審査（4.2）で却下されやすい。
  - Android の Web アプリ（PWA）は、インストールの提案・ホーム画面への表示・通知に対応しており、ネイティブとの差が小さい。
  - iPhone の PWA は、自分で「ホーム画面に追加」する必要がある。追加率の公開データはないが、追加してもらいにくいという見解は一致している。
  - 友人から友人へ広げる際に共有するのは、ネイティブアプリの有無にかかわらず Web リンクが合理的（どの端末でも開け、招待情報が渡る）。

## Options considered

| Option | メリット | デメリット | 結果 |
|---|---|---|---|
| Web・iOS・Android をネイティブ含めすべて（Expo） | どの端末でもストアから入れられる | Android は 12 人テストの壁。作る量・審査・Apple 年 約 12,980 円 | 不採用 |
| Web ＋ iOS ネイティブ | 友人に多い iPhone で App Store から入れられる | ネイティブ未経験。Expo だと Web の自由度が下がる。Apple の費用と審査 | 不採用 |
| Web ＋ Web を包んだアプリ | コードは 1 つ | 審査 4.2 で却下されやすい | 不採用 |
| **Web のみ（PWA としてホーム画面に追加できる）** | 開発が最も楽で、Web の専門性をフルに生かせる。費用・審査なし。どの端末でも同じリンクで開ける。ログインなしでの閲覧も自然 | iPhone では「ホーム画面に追加」を自分でしてもらう必要があり、人づてに広がるほどされにくい | **採用** |

## Decision

Web のみで提供する（ホーム画面に追加して使える PWA）。

## Why

- 開発者の判断（2026-09-28）。1 人・週 10 時間の開発と保守で、最も単純で速い。
- 開発者の得意分野（Web フロントエンド）をそのまま生かせる。
- Apple / Google の費用・審査・テスト要件がなく、予算の目安（年 1 万円）に収まる。

## Tradeoffs / Consequences

- iPhone の利用者にホーム画面へ追加してもらうための案内が、体験の重要な一部になる。
- 共有されるリンクが LINE のアプリ内ブラウザで開かれる前提で、設計する必要がある。
  - 招待リンクに `openExternalBrowser=1` を付ける。
  - アプリ内ブラウザでも失敗しないログイン方式にする。
- iPhone の通知は、ホーム画面に追加した人だけが受け取れる（通知は MVP の範囲外）。
- ログインなしでの閲覧を MVP に含める（[mvp](../product/mvp.md) の条件「Web の場合のみ」を満たす）。

## Revisit when

- 公開後、iPhone の友人がホーム画面に追加せず、使われなくなる傾向が見えたとき（→ iOS ネイティブアプリの追加を検討。Web は招待の入り口として残る）
- 通知が利用継続に不可欠だと分かったとき
