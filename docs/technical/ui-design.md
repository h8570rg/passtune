# UI Design（モデルベース UI デザイン）

- Phase: 11
- Last updated: 2026-10-11
- 状態: [PROPOSED]（開発者の指示により AI の判断で設計・実装まで進める。2026-10-11）
- 手法: 開発者の指示により、モデルベース UI デザイン（オブジェクト指向 UI デザイン、OOUI）の手順で設計する。
  - 出典: ソシオメディア・上野学・藤井幸多『オブジェクト指向UIデザイン ― 使いやすいソフトウェアの原理』（技術評論社、2020）。設計の 3 ステップ「オブジェクトの抽出 → ビューとナビゲーションの検討 → レイアウトパターンの適用」（[ソシオメディア](https://www.sociomedia.co.jp/10046)）。
  - あわせて「ユースケースの洗い出し」「関係と例外（0 件など）の検討」「ナビゲーションを UI より先に設計する」「画面ではなくビューと呼ぶ」の考え方を取り入れる（[GORO「モデルベースUIデザイン読んだよ。」](https://note.com/bibimuu12/n/nc0706ded2446)）。
- 根拠: [mvp](../product/mvp.md), [strategy](../product/strategy.md), [database](database.md)

| # | 誰が | 何を | どうできる |
|---|---|---|---|

## 2. オブジェクトの抽出

ユースケースの名詞から、利用者が直接扱う「オブジェクト」を抽出する。

| オブジェクト | 主なプロパティ | アクション（CRUD） | 備考 |
|---|---|---|---|
| **投稿（Post）** | 曲、一言、投稿者、日時、いいね数、コメント数、延べ再生回数（投稿者のみ） | 作る、見る、削除 | 中心のオブジェクト |
| **曲（Track）** | 曲名、アーティスト、アルバム、ジャケット、試聴、各サービスのリンク | 検索する、試聴する、各サービスで開く | Apple のデータ。投稿の一部として表示する |
| **利用者（User / Profile）** | ID、表示名、アイコン、投稿一覧、フォロー数、フォロワー数 | 見る、フォローする、（自分）編集 | |
| **コメント（Comment）** | 本文、書いた人、日時 | 作る、見る、（自分）削除 | 投稿に従属 |
| **反応（Activity）** | 種類（いいね / コメント）、誰が、どの投稿に、日時 | 見る | いいねとコメントを「自分宛て」として束ねた見え方 |

- いいね・フォローは、オブジェクトではなく「関係」として扱う（投稿・利用者のアクションと件数で表す）。
- 招待リンクは、自分のプロフィールのアクション（「招待リンクをコピー」）として扱う。

### 関係と例外

| 関係 | 多重度 | 0 件のとき（例外パターン） |
|---|---|---|
| 利用者 → 投稿 | 1 対多 | プロフィール: 「まだ投稿がありません」（自分なら「最初の 1 曲を投稿」ボタン） |
| 利用者 ⇄ 利用者（フォロー） | 多対多 | タイムライン: 誰もフォローしていない → 自分の投稿だけ表示し、招待リンクのコピーを促す |
| 投稿 → コメント | 1 対多 | 「最初のコメントを書く」 |
| 自分の投稿 → 反応 | 1 対多 | 反応: 「まだ反応はありません」 |
| 曲の検索結果 | 0〜n | 「見つかりませんでした。曲名とアーティスト名で試してください」 |
| 曲 → 試聴 | 0〜1 | 試聴音源がない曲: 再生ボタンを無効にし、各サービスで開くボタンだけ出す |

## 3. ビュー

各オブジェクトに、一覧（コレクション）と 1 件（シングル）のビューを与える。

| オブジェクト | コレクションビュー | シングルビュー |
|---|---|---|
| 投稿 | タイムライン、プロフィール内の投稿一覧 | 投稿詳細（曲・試聴・各サービス・いいね・コメント一覧） |
| 曲 | 検索結果（投稿作成の中） | ―（投稿のカード・投稿作成の選択状態として表示） |
| 利用者 | フォロー一覧、フォロワー一覧 | プロフィール |
| コメント | 投稿詳細の中のコメント一覧 | ―（一覧の 1 行で足りる） |
| 反応 | 反応一覧 | ―（行を押すと対象の投稿詳細へ） |

### 投稿カード（コレクション内の 1 件）

投稿者（アイコン・表示名・ID・日時）→ 一言 → 曲（ジャケット・曲名・アーティスト・再生ボタン）→ 各サービスのボタン列 → いいね・コメント数（自分の投稿なら延べ再生回数）。

- タイムラインで試聴・各サービスで開く・いいねまで完結できるようにする（原則 1「聴くまでの手間を最小にする」）。
- 試聴の近くに「Listen on Apple Music」と「provided courtesy of iTunes」、ボタン列は Apple Music を先頭（[music-terms](../research/2026-09-28-music-terms.md)）。

## 4. ナビゲーション

### 全体像

```
[ルート（ログイン後）]
  ├─ ホーム = タイムライン（投稿のコレクション） ── 投稿詳細 ── 投稿者のプロフィール
  ├─ ＋ 投稿する（曲の検索 → 選択 → 一言 → 投稿）
  ├─ 反応（反応のコレクション） ── 投稿詳細
  └─ 自分のプロフィール ── プロフィール編集 / 招待リンクをコピー / フォロー・フォロワー一覧 / ログアウト

[ログインなし]
  投稿詳細・プロフィール（読むだけ。操作しようとするとログインへ）
  トップ（サービスの説明・ログイン）
```

- 最上位は、主要オブジェクトのコレクション（タイムライン・反応・自分）と「投稿する」。スマホでは下部のタブ、PC では同じ並びの縦ナビ（画面左）にする。
- 「投稿する」はタスク起点だが、投稿は最頻の作成アクションなので最上位に置く（OOUI でも作成は例外的に入口に置いてよい）。

### URL

| ビュー | URL | ログイン |
|---|---|---|
| トップ（未ログイン）/ タイムライン（ログイン後） | `/` | 任意 |
| ログイン（メール → コード入力） | `/login` | 不要 |
| OAuth のコールバック | `/auth/callback` | ― |
| 初回のプロフィール作成 | `/onboarding` | 必須 |
| 投稿する | `/new` | 必須 |
| 投稿詳細 | `/posts/[id]` | 任意 |
| プロフィール | `/u/[handle]` | 任意 |
| フォロー / フォロワー一覧 | `/u/[handle]/following`、`/u/[handle]/followers` | 任意 |
| 反応 | `/activity` | 必須 |
| プロフィール編集 | `/settings` | 必須 |
| 招待リンク | `/i/[handle]` | 任意（招待者を記録してログインへ） |
| Spotify への転送 | `/go/spotify/[postId]` | 任意 |
| 利用規約 / プライバシーポリシー | `/terms`、`/privacy` | 不要 |

### 状態遷移（主なもの）

- 未ログインで操作（いいね・コメント・フォロー）→ `/login?next=<元の URL>` → ログイン後に元のビューへ戻る。
- ログイン直後にプロフィールがない → `/onboarding`（ID・表示名・アイコン）→ 招待があれば招待者を自動フォロー → `/`。
- 投稿する: 検索（入力のたびに候補）→ 候補の試聴 → 選択 → 一言 → 投稿 → 投稿詳細へ。
- 投稿・コメントの削除: 確認ダイアログ → 削除 → 一覧へ戻る。

## 5. モーダル / モードレス

| 操作 | 方式 | 理由 |
|---|---|---|
| 削除の確認 | モーダル（ダイアログ） | 取り消せない操作 |
| ホーム画面への追加の案内 | モードレス（閉じられるバナー） | 使い方を妨げない（原則 5） |
| 投稿する | 独立したビュー（`/new`） | 検索・試聴・入力と手順が多い |
| コメントの入力 | モードレス（投稿詳細の下部に常に表示） | 読みながら書ける |
| 試聴 | モードレス（同時に 1 曲だけ再生。別の曲を再生すると前の曲は止まる） | どこからでも聴ける |

## 6. レイアウトとビジュアル

- **モバイルファースト。** 1 カラム（最大幅 640px 程度）を中央に置き、PC でも同じ構成にする。
- **配色:** ライト / ダークの両対応（端末の設定に従う）。アクセントは落ち着いたインディゴ 1 色。各音楽サービスのブランドカラー（Apple の赤、Spotify の緑など）と競合しないようにする。
- **文字:** 端末の標準フォント（日本語の Web フォントは読み込まない。軽さを優先）。
- **部品:** HeroUI v3 を使い、角丸はやや大きめで柔らかい印象にする。
- **アイコン画像:** アップロードしていない人は、表示名の頭文字の丸いアイコン。
- **音楽サービスのボタン:** 各社のロゴのガイドラインに沿う（[music-terms](../research/2026-09-28-music-terms.md)）。公式素材を入手するまでは、サービス名の文字ボタンで代用する（ロゴの差し替えは公開前の確認事項）。
